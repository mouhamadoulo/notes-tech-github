Voici un **tuto complet du vocabulaire autour d’un projet informatique**, organisé comme dans un vrai projet en entreprise pour que tu comprennes les mots dans leur contexte.

---

# 1. Les grandes phases d’un projet informatique

Un projet informatique suit généralement un cycle de vie :

### 🧠 Cadrage (ou conception)

C’est la phase où on définit **ce qu’on veut faire**.

* **Besoin utilisateur** : ce que les utilisateurs veulent réellement
* **Cahier des charges** : document qui décrit tout le projet (fonctionnalités, contraintes, budget)
* **Spécifications fonctionnelles** : ce que le logiciel doit faire
* **Spécifications techniques** : comment on va le construire

---

### 🏗️ Développement

C’est la phase de construction du logiciel.

* **Code source** : ensemble du code écrit par les développeurs
* Git : outil pour gérer les versions du code
* **Commit** : sauvegarde d’un changement dans Git
* **Branch (branche)** : version parallèle du code
* **Merge** : fusion de plusieurs branches

---

### 🧪 Tests

On vérifie que tout fonctionne correctement.

* **Bug** : erreur dans le logiciel
* **Test unitaire** : test d’une petite partie du code
* **Test d’intégration** : test de plusieurs modules ensemble
* **Recette** : validation finale par le client

---

### 🚀 Déploiement

On met le logiciel en production.

* **Production** : version utilisée par les utilisateurs
* **Staging** : environnement de test proche de la production
* **Release** : mise en ligne d’une nouvelle version

---

# 2. Les méthodes de gestion de projet

### 📌 Méthode classique (cycle en V)

* Tout est planifié à l’avance
* Peu flexible
* Adapté aux projets très cadrés

---

### 🔁 Méthodes Agile

Agile software development est une approche flexible basée sur des cycles courts.

Vocabulaire associé :

* **Sprint** : période courte (1 à 4 semaines)
* **Backlog** : liste des tâches à faire
* **User story** : besoin exprimé du point de vue utilisateur
* **Itération** : cycle de développement répété

---

### 🧩 Scrum

Scrum est un cadre de travail Agile très utilisé.

Rôles importants :

* **Product Owner** : définit les priorités
* **Scrum Master** : facilite le travail de l’équipe
* **Équipe de développement** : construit le produit

Événements Scrum :

* **Daily stand-up** : réunion quotidienne rapide
* **Sprint planning** : planification du sprint
* **Sprint review** : démonstration du travail
* **Rétrospective** : amélioration continue

---

# 3. Les pratiques modernes de développement

### ⚙️ DevOps

DevOps est une approche qui combine développement et exploitation.

Vocabulaire clé :

* **CI (Continuous Integration)** : intégration continue du code
* **CD (Continuous Delivery/Deployment)** : livraison automatique
* **Pipeline** : chaîne d’automatisation
* **Monitoring** : surveillance du système

---

# 4. Les outils courants d’un projet

### 🧑‍💻 Gestion de projet

* Jira : gestion des tâches et bugs
* **Ticket** : tâche ou problème à traiter
* **Epic** : grande fonctionnalité découpée en tâches

### 💬 Communication

* **Slack / Teams** : messagerie d’équipe
* **Réunion quotidienne** : point rapide sur l’avancement

### 📦 Déploiement & infrastructure

* **Serveur** : machine qui héberge l’application
* **API** : interface entre logiciels
* **Base de données** : stockage des informations

---

# 5. Les rôles dans une équipe informatique

* **Chef de projet / Product Owner** : décide des priorités
* **Développeur** : écrit le code
* **Testeur (QA)** : vérifie la qualité
* **DevOps engineer** : gère les déploiements et serveurs
* **UX/UI designer** : conçoit l’interface utilisateur

---

# 6. Petit glossaire rapide

* **Feature** : fonctionnalité
* **Release** : version livrée
* **Rollback** : retour à une ancienne version
* **Hotfix** : correction urgente
* **Deadline** : date limite
* **Scope** : périmètre du projet

---

# 7. Comment tout ça s’articule (exemple simple)

1. Le Product Owner écrit une **user story**
2. L’équipe la met dans le **backlog**
3. Elle est planifiée dans un **sprint**
4. Les développeurs codent avec **Git**
5. Les tests vérifient les **bugs**
6. Le produit est déployé via un pipeline **DevOps**
7. Les utilisateurs utilisent la nouvelle **release**
