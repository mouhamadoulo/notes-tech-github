	Outils métier IHM pour la facturation , le roaming, les numéros spéciaux, le routage international
	développés par le métier sur un coin de table 
	hébergé sur des machines dédiés (faible stockage, RAM insuffisante, OS anciens, accès à des bases prod non autorisés, …)
	la MOE a repris ces outils , et a lancé un projet de sécurisation dessus pour être en phase avec les normes sécurité de Bouygues 

-- Dans un premier temps une Prise en main des outils , Maintenance corrective et évolutive avec des EBs fournis par le métier

Projet 1 : Première Migration des outils dans une zone sécurisée
- commande des nouveaux serveurs de prod (avec le minimum requis en stockage, RAM, ...)
- configuration et Installation des technos sous jacente (les SGBD, les Serveurs web, les outils, ...)
- Déplacer les IHM front et les traitements back dans ces serveurs
- mise en place de flux fichiers sécurisés entre les STs (via STF)
- Tests de connectivité avec les autres ST, Tests des fonctionnalités , Tests de non régression 
- échange avec le métier , communication sur les tests, retours des tests métiers aux devs
- journée sur le plateau des métiers pour voir un peu comment ils utilisent les outils ihm , le parcours	qu'ils font pour réaliser leur tâches

-- Correction de bugs
-- Des EBs d'évolution entre temps sont arrivés au fil du temps sur les différents outils 
-- Des évolutions front et back


Projet 2 : Deuxième Migration dans le cloud AWS
- cloudifier les outils (ihm, bases de données , système de fichiers)
- prise en main des services de AWS (EC2, RDS, bucket S3 , AWS Lambda, ...)
- échange avec plusieurs équipes (dev, équipe cloud, équipe DBA, équipe sso, équipe stf, exploitant, métier)
- Mise en place du CI/CD (prise en main des outils de la chaine DevOps , Gitlab CI/CD, Artifactory, iDeploy, …)
- chiffrage , planification , challenger le chiffrage pour voir qu'est ce qu'on peut optimiser
- fonctionnement en mode agile (daily tous les matins)
- s'assurer que les environnements de tests sont OK et bien fournis pour effectuer les tests
- point avec l'équipe d'exploit en début de projet 
- point avec le métier en phase de recette (2 par semaines) pour avoir les retours sur les tests 
		
-- Amélioration de plusieurs traitements Talend et procédures stockées destinés au chargement et à l'agrégation de fichiers tap sur le roaming avant les JO 2024

Projet 3 : Développement de Traitements et Batchs Springboot pour un DATAWARE de 4 schémas sur Oracle nommé SHELTER
- Création de Batchs de chargement Springboot pour charger des données de base à base ou fichier à base
- Refonte de traitements Talend en du Java pur avec utilisation de la librairie Apache Spark
- Création de modules batch Springboot (module de comparaison de fichiers, module de recyclage de tickets rejetés de la queue RabbitMQ)

Exemple Process Projet :
------------------------
-Daily avec l'équipe de DEV dans l'objectif de suivre l'avancement des devs , les points de blocage éventuels
-Point en début de projet avec l'équipe d'exploit pour leur présenter un peu le projet afin qu'ils affectent des ressources dessus
-Point avec le responsable d'équipe 1 fois par semaine sur le suivi de l'avancement du projet
-Point Recette métier pour avoir les retours de tests (1 ou 2 fois par semaine)
-Communication par mail de l'avancement du projet chaque 2 semaines ou chaque fin de semaine si besoin

Le rôle du Chef de Projet est de veiller au bon déroulement des différentes phases du projet en s'assurant de la 
conformité de la solution technique aux besoins initiaux tout en maitrisant les couts et les délais.
Compétences à avoir : 
	=> Compétences Techniques
	=> Esprit analytique : comprendre les besoins et proposer des solutions 
	=> Travail en équipe : collaboration avec développeurs, QA, DevOps, métier, …
	=> Leadership : capacité à motiver et coordonner des équipes techniques.
	=> Résolution de problèmes : prise de décision rapide et efficace.
	=> Adaptabilité : face aux changements technologiques et aux imprévus.
	=> Comment anticiper ? 
	=> Comment chiffrer ? 
	=> Comment planifier ? 
	=> Comment gérer les risques liés au projet ? 
	=> Comment gérer les différents intervenants du projet ? 
	=> Comment bien communiquer durant tout le processus du projet ? 
	=> Comment gérer des conflits ? 
	=> Comment rassurer les clients ? 
	=> Comment aider la partie technique ? Comment les motiver ? Comment les aider à bien avancer ? 
	=> Comment bien tester les livrables ? 
	=> Comment faire une bonne documentation au cours du projet ?
